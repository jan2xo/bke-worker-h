# F3-00 Adversarial Security Audit of F2 Authorization, Authority & Credential Path

This audit evaluates the BKE Desktop Worker F2 implementation from an **independent-reviewer perspective** before broker integration. Each finding maps directly to an implemented hardening fix in F3.

---

## Audit Area A — Signed Execution Envelope & Replay Security

| Threat | Affected Component | Existing F2 Mitigation | Evidence / Finding | Residual Risk | Recommended F3 Correction (Status) | Priority | Acceptance Test |
|---|---|---|---|---|---|---|---|
| **A1. Shared HMAC Key Forgery (Desktop Compromises Server Authority)** | `github-app-harness.ts`, `controller-daemon.ts` | HMAC-SHA256 `signingKey` isolated per `keyId`; `key_id` checked against `executionSigningKeysById`. | V1 HMAC uses a symmetric shared secret. If the desktop host is compromised, an attacker extracting `BKE_EXECUTION_SIGNING_KEY` can forge execution envelopes. | **High** if desktop secret leaks in V1-only deployments. | **IMPLEMENTED (F3-00/F3-03):** Introduce V2 Ed25519 asymmetric protocol (`protocol_version: 2`, `'BKE_EXECUTION_REQUEST_V2\n'` domain separator) signed by broker private key and verified on desktop with public keys only; add strict `requireAsymmetricV2` flag (`EXEC_REQ_DOWNGRADE_FORBIDDEN`). | **P0** | `f3-hardening.test.mjs` (#1), `broker-service.test.mjs` (#2, #16) |
| **A2. HALT Key / Execution Key Confusion** | `controller-daemon.ts`, `github-app-harness.ts` | Separate config maps (`executionSigningKeysById`, `remoteHaltSigningKeysById`). | V1 checked raw secret identity inside daemon constructor, but V2 public keys also need non-overlap plus rejection of execution keys attempting `HALT` verification. | **High** if operator pastes identical PEM for both. | **IMPLEMENTED (F3-00):** Reject shared PEM/material across `executionPublicKeysById` & `remoteHaltPublicKeysById` in both `ExecutionRequestVerifier` (`EXEC_REQ_HALT_KEY_SEPARATION_REQUIRED`) and `DesktopControllerDaemon` constructor (`DAEMON_HALT_KEY_SEPARATION_FORBIDDEN`). | **P0** | `f3-hardening.test.mjs` (#1, #4), `broker-service.test.mjs` (#16) |
| **A3. Stale/Revoked Device Replaying Envelopes or Minting Tokens** | `github-app-harness.ts`, `device-enrollment.ts` | Persistent `delivery_id` & `attempt_id` replay store (`FileExecutionJournal` + `PersistentReplayStore`). | V1 envelopes had no `device_id`, `enrollment_generation`, `audience`, or `broker_issuer`, so revoking a lost laptop could not invalidate newly presented envelopes signed before rotation. | **Medium–High** during lost-device response. | **IMPLEMENTED (F3-00/F3-02):** Bind V2 envelopes to `broker_issuer`, `audience`, `device_id`, and `enrollment_generation >= minEnrollmentGeneration`, plus pluggable `deviceRevocationChecker` (`EXEC_REQ_DEVICE_REVOKED`). | **P0** | `f3-hardening.test.mjs` (#1), `chaos-adversarial.test.mjs` (#10) |
| **A4. Daemon Constructor Missing Brace / Boot Regression** | `controller-daemon.ts` | `tsc --noEmit` & unit tests. | Detected pre-F3 syntax/wiring gap in V2 key-separation block during refactor. | **Critical** if uncompiled. | **FIXED & VERIFIED:** Closed constructor scope cleanly and verified strict TypeScript compile (`tsc`) + full suite. | **P0** | `controller:build`, `f3-hardening.test.mjs` (#4) |

## Audit Area B — GitHub Authority & Ledger Security

| Threat | Affected Component | Existing F2 Mitigation | Evidence / Finding | Residual Risk | Recommended F3 Correction (Status) | Priority | Acceptance Test |
|---|---|---|---|---|---|---|---|
| **B1. HTTP 3xx Redirect Following Leaking Installation Bearer Token** | `github-authority-provider.ts`, `github-f1-ledger.ts` | Custom header allowlist (`Accept`, `Authorization`), strict host URLs. | Default `fetch()` behavior follows HTTP 301/302/307/308 redirects automatically, risking `Authorization` header disclosure or open-redirect response spoofing (by contrast, `cloudflare-relay/src/github-app.js:495` already mandated `redirect: "manual"`). | **High** against MITM or misconfigured proxy redirects. | **IMPLEMENTED (F3-00):** Add `redirect: 'manual'` to ALL GitHub HTTP fetches in `RestGitHubAuthorityProvider` and `GitHubF1Ledger` (plus `SandboxGitHubAppAdapter`), failing closed on `300 <= status < 400` (`GITHUB_REDIRECT_BLOCKED`). | **P0** | `f3-hardening.test.mjs` (#2) |
| **B2. GitHub `maintain` / Empty Repository Permission Bypass** | `github-authority-provider.ts` | Rejected `admin === true`. | GitHub repository payload can specify `maintain: true` or return an empty/missing `permissions` object `{}` when installation grants diverge or degrade. | **Medium** privilege ambiguity. | **IMPLEMENTED (F3-00):** Fail closed when `permissions` is missing/empty (`GITHUB_REPOSITORY_PERMISSIONS_MISSING`) or `maintain === true` (`GITHUB_PERMISSION_FORBIDDEN`). | **P1** | `f3-hardening.test.mjs` (#2) |
| **B3. Hardcoded `https://api.github.com` in `verifyInstallationRepository()`** | `github-f1-ledger.ts` | Injectable `fetchImpl` mock for unit tests. | `GitHubF1Ledger` hardcoded `this.baseApi = 'https://api.github.com'`, preventing separate OS daemon processes from targeting local `MockGitHubServer` via HTTP in sandbox E2E without code patching. | **Medium** (limits true multi-process E2E verification). | **IMPLEMENTED (F3-00/F3-04):** Added optional `baseApiUrl?: string` on `GitHubF1LedgerConfig` defaulting cleanly to `'https://api.github.com'` and applied consistently to both `baseApi` and `repoRoot`. | **P1** | `f3-hardening.test.mjs` (#2), `multiprocess-e2e.test.mjs` |
| **B4. Single-Repo Token Blind Spot for Cross-Repo Worker PR Conflicts** | `github-authority-provider.ts` (desktop) vs `SandboxGitHubAppAdapter` (broker) | Single-repo `/pulls` + `/installation/repositories` repo count verification. | If `worker-f1` is assigned on PR #149 in `jan2xo/bke-worker` AND also holds an open labeled PR in a *second* repo in the same App installation, a single-repo token on the desktop cannot inspect pulls in the second repo. | **Medium** when installation covers multiple repos. | **IMPLEMENTED IN BROKER (F3-03):** `SandboxGitHubAppAdapter.verifyExecutionAuthority()` enumerates open pulls across ALL installation repositories before signing an execution request, rejecting `BROKER_CROSS_REPO_WORKER_CONFLICT`. | **P1** | `broker-service.test.mjs` (F3-05 cross-repo PR) |

## Audit Area C — Credential Lifecycle & Failure Handling

| Threat | Affected Component | Existing F2 Mitigation | Evidence / Finding | Residual Risk | Recommended F3 Correction (Status) | Priority | Acceptance Test |
|---|---|---|---|---|---|---|---|
| **C1. Ambiguity Between Transient Broker Outage vs Uncertain Send/Write** | `token-lifecycle.ts`, `desktop-controller.ts` | Single-attempt `issueToken()`, separate `DELIVERY_UNCERTAIN` quarantine in ledger/controller. | Transient `TOKEN_BROKER_UNAVAILABLE` / `TOKEN_BROKER_TIMEOUT` *before* claim/send immediately failed the wake without distinguishing pre-claim retryability from post-claim non-retryable uncertainty. | **Medium** operational fragility during broker restart. | **IMPLEMENTED (F3-00/F3-06):** Added bounded pre-claim retry in `ManagedTokenProvider` (`maxTransientRetries`, strict deadline guard) restricted ONLY to `TOKEN_BROKER_UNAVAILABLE`/`TOKEN_BROKER_TIMEOUT`, classifying recovery safety in `lastRecoveryClassification` (`PRE_CLAIM_AUTO_RETRY_SAFE` vs `NON_RETRYABLE_ERROR`), while preserving strict zero-retry after `POST /git/refs` or DOM send starts. | **P1** | `f3-hardening.test.mjs` (#3), `chaos-adversarial.test.mjs` (#16) |
| **C2. Leaked Bearer Token in Logs/Errors/Status** | `token-lifecycle.ts`, `controller-daemon.ts` | `sanitizeTokenText()` scrubbing `ghs_*`, `gho_*`, Bearer strings. | Audit confirms `getStatus()` exports only booleans/hashes (`valid`, `brokerConnected`, `expired`, `revoked`, `lastRecoveryClassification`) and F3 `SandboxDesktopBroker` audits strip all secrets. | **Low** residual risk when custom extensions log errors. | Preserve sanitization across V2 & broker audit emitters; assert `!serialized.includes('ghs_')` & `!serialized.includes('PRIVATE KEY')` in tests. | **P1** | `broker-service.test.mjs`, `multiprocess-e2e.test.mjs` |

## Audit Area D — Architectural Limits & Production Ownership Gap

| Threat | Affected Component | Existing F2 Mitigation | Evidence / Finding | Residual Risk | Recommended F3 Correction (Status) | Priority | Acceptance Test |
|---|---|---|---|---|---|---|---|
| **D1. Desktop Possession of `contents: write` Installation Token** | `RestGitHubAuthorityProvider` / `GitHubF1Ledger` | Tokens clamped to single `repository_id` and `contents: write` max, short TTL (`180s`). | Even a single-repo `contents: write` token could technically overwrite other refs on that repository if desktop were compromised (outside canonical PR protection rules). | **Medium** blast radius inside bound repository. | **PROTOTYPED (F3-03):** Implemented `executeServerMediatedLedgerOp()` supporting **only** 4 allowlisted CAS operations (`COMMIT_PRE_SEND_FENCE`, `CONSUME_SEND_CLAIM`, `RECONCILE_CONVERSATION`, `MARK_DELIVERY_UNCERTAIN`), failing closed on arbitrary ref paths (`BROKER_ARBITRARY_PROXY_FORBIDDEN`)—demonstrating zero `contents: write` exposure on desktop in a future production phase. | **P2** | `broker-service.test.mjs` (#17) |
| **D2. Frozen Production Boundary (`cloudflare-relay/` & `jan2xo/bke-worker`)** | `cloudflare-relay/`, live GitHub App, live Chrome. | Remote broker stub disabled by default (`REAL_BROKER_TRANSPORT_DISABLED_NOT_AUTHORIZED`); F3 broker quarantined in `integrations/desktop-broker/`. | Cannot safely activate in production until owner audits `cloudflare-relay` binding changes, provisions broker signing keys, and signs off Level 7 Chrome session. | **Blocked by Governance** (intentional). | Keep all V2/remote-broker env flags `false` in `deploy/desktop-controller.env.example` and enforce in `package-desktop-worker.sh` + CI. | **P0** | `package-desktop-worker.sh`, `controller:doctor` |
